# 算法第一版：最大瓶颈阈值内的共享资源定价匹配

2026-11-12。本轮实质修改了分解算法，不是只补组件。版本是待继续研究的有界启发式，不宣称全局非退化或投稿完成。

## 1. 具体修改及接口

每轮仍先由S1求最大可行阈值q*。随后只在残量>=q*的正支持图中，用共享资源价格构造边费用，运行真正的最小费用完美指派；不是Kuhn访问顺序调整，也不依赖相邻阶段系数相同。

主要代码：

- `algorithm/all2all.h`：`DecompositionOptions::resource_rounds`，默认0，至多8，只允许S1；`decompose(options,stats,topology,pending)`兼容旧默认调用。新增资源提案/接受计数。
- `algorithm/all2all.cpp::match_resource_priced()`：真实路径贡献缓存、价格更新、带权Hungarian指派、完整阶段时间接受判断。
- `scheduler/global.cpp`：仅启用该选项时透传balance后的真实pending；原生Local、补齐、scaling、dispatch、pipeline递推不改。
- `bvn_decompose_main.cpp`：新增`--resource-rounds 0..8`及计数输出；0保持原S1输出。

没有新增生产类或外部求解器。入口示例：

```text
--mode pipeline --strategy 1 --topology 1 --scaling 1 --resource-rounds 3
```

### 每轮规则

1. 从S1种子匹配计算真实资源工作量 `w[e]=0.008*bytes[e]/Gbps[e]`，不包含虚拟流量。
2. 以归一化工作量初始化资源价格：`price[e] += w[e]/max(w)`。
3. 对允许的服务器对边，以当前真实剩余量裁剪q*，缓存其各资源贡献。边费用是 `sum_e price[e] * edge_work[e]`，单位为us，价格无量纲。
4. 在阈值支持图上做最小费用完整指派。禁边不参与松弛，不用有限罚项冒充合法边。
5. 用原有 `Topology::evaluate_gpu()` 评价整个试探匹配，只有当前阶段的完整代价（含传播）严格低于本轮已保留匹配才替换。试探匹配即使未被接受，其负载也用于下一次价格累加，探索固定3轮后停止。
6. 原生扣减入口按实际最小残量提取，更新真实pending并进入下一轮。不得删除需求、增加虚拟服务奖励或无限重试。

价格费用是不可分共享最大值目标的线性代理，不是精确最优目标。传播没有与字节线性相加，而在完整阶段接受目标中单独处理。路径缓存可复用，但本阶段真实贡献随q和残余更新。

### 保护什么、不保护什么

因为q*是最大可行阈值，阈值图中的任意完美匹配实际最小残量必为q*；否则会有更大的可行阈值。代码再次验证实际min。所有策略仍共用原生残余扣减、精确交付与终止逻辑。

只保证在**当前实际前缀状态下**不选择比S1种子更贵的阶段；改变匹配会改变后续残余，因此不保证整个计划K不增或总时间下降。完整FAST的dispatch重叠也没有作为该局部接受式的一部分。不能将这个局部护栏写成全局性能证明。

额外复杂度为每个分解阶段至多B次O(n³)带权指派，加真实路径贡献缓存与B次资源评分；B=3固定，不随支持图线性增加。`decomposition_cpu_us`在启用时包含缓存、评分、价格和指派，未将新模型计算排除在规划内；旧未启用路径仍是原有口径。

## 4. 为什么仍会失败

**N16大微扰：不是机内重叠造成。** 两方案均15阶段，未隐藏机内时间均约4.90us。新方法传播和从792降到586.4us，却使累计序列化从43517.5424升到47784.4275us，整体慢9.17%。这表明本轮便宜的匹配仍可留下更差的未来资源组合；需要研究跨阶段残余影响，而不是把该损失解释成“只有阶段变多”。目前尚未逐步定位首个导致不可逆损失的匹配。

**N8大Zipf：碎片和资源组合同时退化。** K从40增到42，传播从2060.6升到2166.2us，序列化从26815.529升到27681.587us，导致整体变慢。说明仅保护当前q*并不能保护未来分解粒度。

**N16大Zipf：多一阶段仍可更快。** K从91增到92，传播几乎不变，累计序列化从60199.4035降到55230.7098us，产生约4.967ms收益。这是联合目标不能由阶段数单独代替的正例。

## 5. 规划成本仍是实际约束

最终记录中，N16小Zipf：S1分解CPU中位数89us，新方法839us，预计通信仅减少360us。仅按CPU与通信串行相加的预算，新增计算已抵消通信收益；因此不能声称小负载在线净收益。

N16大Zipf：S1分解CPU1586us，新方法3677us；通信减少4967us，仍有预算余量。全规划墙钟1816→3888us（含机内计划，受系统调度影响），不能将这些简单相加冒充真实实机端到端时间。需进一步限定启动条件或降低评分/指派成本，不能只呈现通信加速。
