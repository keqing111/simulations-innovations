# 剩余并行机会：先区分匹配没找到与当前目标不够好

## 1. 先修正一个容易误解的因果结论

上一轮“只撤销一次修改后，恢复同一算法”的耗时结果仍然成立。但它衡量的是**一个动作加上该算法后续行为**，并不证明动作本身已经不可挽回地破坏了余下调度。

这一区别在3DC异构WAN大负载例子中非常重要：

- 原资源方案网络阶段合计32.170593ms，完整操作32.184692ms。
- 只撤销首个纯DC内阶段的修改，完整操作降为29.036297ms；这是已验证的同策略反事实。
- **保留原首阶段，后续实际仍存在网络合计21.931248ms的分解。**

因此，不能从撤销实验推出“首个纯LAN阶段消耗了不可恢复的搭配机会”。本轮精确核查发现，真正的不可恢复损失在第2阶段；它属于候选生成不足。另一个共享网关例子才证明，即使生成了当前阶段的真正最优匹配，也可能损害后续。

## 2. 本轮实现与比较边界

只增加一个[离线诊断脚本](residual_opportunity.py)和对应测试，没有修改FAST的默认匹配算法、资源价格公式、scaling、balance、dispatch或网络计价模型。

输入沿用上一轮已对账的三种3DC×2server×4GPU配置：独立100Gbps WAN；100Gbps共享网关；50/100/200Gbps及不同传播时延的异构WAN。具体路径与负载定义见[此前报告第5节](CAUSAL_AND_MULTIDC_REPORT.md)。

本轮覆盖：

- 原三个失败输入中的23次单决策干预，检验轻量指标能否解释原策略的后续结果。
- 严格均匀的3拓扑×2字节档×3方法，共18份轨迹、90个实际前缀。
- 每个均匀前缀的合法动作、最佳剩余网络时间，以及2/3条匹配边交换的可行性。
- 四种评分在6个均匀条件上的离线逐阶段选择；这部分枚举所有合法动作，**不是在线算法性能结果**。

所有结果仍在同一容量近似模型内：阶段网络时间为最大单向传播时间加最大资源序列化工作。保留原阶段边界，不引入ns-3或新增barrier。

## 3. 如何确认“后续损失”是否不可恢复

对一个当前状态和动作，区分：

```text
V(当前状态) = 从当前状态出发，可以达到的最小剩余网络时间
Q(动作) = 当前阶段网络时间 + V(执行该动作后的状态)
不可恢复损失 = Q(动作) - V(当前状态)
当前策略差距 = 当前算法实际剩余网络时间 - V(当前状态)
```

第一项损失排除了“后面本可以改好，只是该算法没有改好”的影响。它与先前的恢复同策略反事实不是同一个量。

这里仅在**n<=6、等正辅助系数、等真实GPU载荷、每条正边只需访问一次、无对角或完全虚拟支持边**的规则图上计算精确值。允许原生scaling把容量向上取整，但绝不把空余容量计作真实字节。

这些限制下，每次选择完美匹配后删去六条已完成的边；每条边的真实载荷固定，阶段网络代价与执行次序无关。因此可以按剩余边集合做记忆化动态规划，并固定本轮覆盖第一条剩余边以消除阶段排列重复，不丢失任何无序分解。

这不是一般BvN全局求解器。它不适用于变系数、非均匀残量、partial matching或未知网络状态，也没有接入在线代码。它求的是**受限模型内的网络时间最优值**，没有把观测到的dispatch尾部直接当成新分解下已验证的FAST完成时间。

## 4. 第一类不足：资源线性价格未生成真正的低峰值匹配

### 4.1 损失明确发生在第2阶段，而非第1阶段

异构WAN、大负载、均匀需求的当前资源方案：

| 阶段（从1开始） | 实际网络时间，ms | 此阶段动作的不可恢复损失，ms |
|---|---:|---:|
| 1 | 0.641359 | 0 |
| 2 | 10.442145 | **10.239345** |
| 3 | 5.322472 | 0 |
| 4 | 5.322472 | 0 |
| 5 | 10.442145 | 0 |

第5阶段很慢，但到那时只剩一个合法匹配，不能把责任归到该阶段。第2阶段既多花了5.119672ms，又把后续最优时间提高了5.119672ms，两部分合计10.239345ms。

保留第1阶段，一个最优的后续组合能使剩下四个阶段均为5.322472ms。因此本例不需要否决首个纯LAN阶段。

### 4.2 一个具体的三边修改，而不是笼统“再搜索几次”

第2阶段的原匹配为：

```text
server目的列表：[3, 2, 5, 4, 1, 0]
DC归属：        [0, 0, 1, 1, 2, 2]
```

它在0→1、1→2、2→0三个WAN方向各发送两条server对流；其中慢WAN 0→1承受双份工作。

将源server 1、3、5的目的按一个交替环轮换：

```text
源1：目的2 → 4
源3：目的4 → 0
源5：目的0 → 2
得到：[3, 4, 5, 0, 1, 2]
```

现在六个WAN方向各一条流；端点仍是完美匹配，边均在当前正残余支持中，提取系数和真实流量均不变。网络时间从10.442145ms降为5.322472ms。

在同一状态，3个合法的两边交换都不能降低当前时间；8个合法三边环中存在上述改进。因此“仅尝试两条边互换”也不是充分修复。

### 4.3 线性资源价格在这个例子中存在表示限制

首阶段清除DC内通信后，每个DC两台server都只能发往其他DC。设x为0→1的流数，则所有DC级可行组合必然为：

```text
0→1、1→2、2→0：各 x 条
0→2、2→1、1→0：各 2-x 条
x只能是0、1、2
```

设一条server对流在50Gbps慢WAN上的工作为u。则x=0或2会有一个慢方向承受2u；x=1让两个慢方向各承受u。当前阶段最大资源工作量在x=1更好。

但当前定价把每条边的资源工作乘价格再求和。在同DC server代价相同的本例中，该线性目标只能写成 `常数 + a*x`：

- a>0时偏好x=0；
- a<0时偏好x=2；
- a=0时三者平局，仍不能严格偏好x=1。

所以，真实的资源峰值最优解可能在标量线性评分的中间，而不在某次有严格优势的指派解上。增加价格迭代次数并不能从这个线性形式中获得对x=1的严格偏好；平局规则或不同生成方法仍可能选中它。这里不声称所有价格法都失败，也不声称这是一般指派问题的定理。

这解释了为什么本例首先需要修改**匹配生成如何表达共享峰值**，而不是先给正确的首阶段加一个剩余惩罚。

## 5. 第二类不足：即使当前阶段真正最优，也可能不可恢复地损害后续

共享100Gbps网关、大负载、严格均匀需求：

| 首阶段选择 | 当前网络时间，ms | 最佳后续时间，ms | 当前+最佳后续，ms |
|---|---:|---:|---:|
| 全部DC内通信（唯一当前最优） | 0.641359 | 20.689889 | 21.331248 |
| 一个完整最优分解中的首阶段 | 5.172472 | 15.570217 | **20.742689** |

表中第二条后续时间为精确总值减当前阶段时间。原动作虽然当前省4.531113ms，但最佳后续多花5.119672ms，净损失588.55904us。即使把后面所有匹配都选到最优，也弥补不了。

该例阶段数仍为5。完整最优分解传播支付从212.6us增加到264us，但序列化从21118.64832us降为20478.68928us，净减少588.55904us。它不是少一个阶段，也不是少付传播，而是多付51.4us传播换来639.95904us资源并行收益。

异构WAN、小负载也存在真正的当前目标反例：唯一当前最优首阶段仅11.39936us，但不可恢复损失为33.60704us。它与大负载的第1阶段结论相反，说明不能固定规定“先LAN”或“先WAN”。

## 6. 已检验的轻量指标：量纲统一，但还不能直接部署

令W[e]为剩余真实字节在资源e上的序列化工作，单位us。每个候选都按实际容量从真实pending扣除后重新评价，不使用虚拟补齐流量。

| 评分 | 定义 | 物理意义及边界 |
|---|---|---|
| 当前阶段 | T | 当前策略的接受目标 |
| 当前+容量下界 | T + max W[e] | 至少还需这么多资源工作；是乐观估计，不是后缀预测 |
| 当前+端点/容量下界 | T + max(容量下界，端点下界) | 端点下界为每行/列剩余通信对的独占完成时间之和的最大值 |
| 当前+WAN二范数 | T + sqrt(sum W[WAN]^2) | 剩余WAN工作集中度代理，不是下界 |

端点项中，每个剩余server对的独占时间为单向传播加该对聚合真实字节/路径最小带宽。一个server在一个阶段只能对应一个对端，所以行/列和是累计网络阶段时间的下界。它不预测共享资源的具体组合。

前三个剩余项/当前项和第四项的单位都是us，没有把字节、计数、时间直接相加，也没有拟合权重。计算一次候选的量级是输入边数乘固定路径长度，加资源数，不需重新完整分解。

结果并不支持直接选一个作为最终评分：

- 容量下界能识别共享网关大负载的上述错误，在该小例子中得到最优网络分解。
- 同一个评分在异构WAN大负载下，确定性离线逐阶段选择得到23.857525ms，差于21.931248ms最优值；它有104个首阶段最小评分动作，而最佳与最差后缀不同。
- 异构WAN小负载中，这几种评分都仍选择错误的首阶段；离线网络时间为1.142579ms，高于1.108972ms最优值。
- 对8server Zipf第8阶段，容量、端点和WAN二范数都偏好原动作，但恢复同一算法后，原动作反而使完整时间多1048.9472us。该结果是同策略反事实，不作为一般非均匀问题的最优性证明。
- 16server微扰第6阶段，当前目标只看到0.32768us节省；三个剩余项都能识别原选择会留下更差的工作分布。指标有局部解释价值，但并不普适。

因此，合法的下界不等于可靠的动作排序。最小化“当前时间+乐观下界”也不保证最小化完整时间。仅有剩余链路总量，不足以表达它们能否在合法匹配中重叠。

## 8. 下一步算法应当分开落实什么

1. **匹配生成对齐共享资源峰值。** 在相同q和正支持图下，先验证轻量的三边交替环修正能否补上已确认的两边局部极小；不引入删边、部分匹配、填充变化或全排列在线求解。必须再查找三边修正仍停滞的状态，而非声称它全局最优。
2. **单独改进剩余代价模型。** 使用共享网关大负载、异构WAN小负载这两个不可恢复反例作为模型门槛；不要用异构大负载的正确首个LAN阶段充当应当被惩罚的样本。容量下界可保留为对照，但不能直接作为最终保证。
3. 两部分冻结后分别做消融，再在新流量种子、放置及拓扑比例上检验通信收益和额外CPU；目前没有做这些独立验证，也没有宣布稳定收益。
