## 写作定位

**工作标题（尚未定名）**：Topology-Aware Birkhoff–von Neumann Scheduling for All-to-All Communication in Heterogeneous Hierarchical Networks

中文：异构多级网络中面向 All-to-All 通信的拓扑感知 Birkhoff–von Neumann 调度。

标题暂不加入 Optimal、Near-Optimal 或 Online：目前没有对应最优性或最终在线开销证据。FAST 是实现参考与主要性能对照，不把文章限制成“修改 FAST 某个函数”的工程报告。

**贯穿全文的问题**：在端点匹配和精确交付约束下，如何用有限规划成本同时控制阶段碎片与共享资源的阶段组合，降低单次 A2A(v) 完成时间？

核心观察分为两层：

- 合法匹配和较大的单轮提取系数，不保证整个分解紧凑。
- 即使阶段数和提取系数完全相同，也不保证共享网络资源组合高效。

希望形成的方法贡献是二者的**有界协同规则**，不是分别采用最大瓶颈匹配和链路评分本身。该规则尚未冻结，不预写成已经完成的贡献。

### 1.1 从端点可行到中间共享资源

交代 A2A(v) 的需求矩阵与非均匀通信背景，用相关文献支持应用动机，不虚构真实训练测量。准确介绍 FAST 已有的机内重整、机间一对一通信和流水线，随后将范围收敛到服务器之间的中间共享资源。

### 1.2 为什么减少阶段还不够

概括两类损失：残余分解碎片会增加阶段成本；相同阶段数下，不同通信对组合仍会改变共享资源工作量。简要指出传播摊销与资源并行存在竞争，避免把“WAN 每轮都忙”设为普遍目标。

## 3. Problem Formulation and Motivation（问题建模与动机，约 700 词）

**目的**：用明确假设和小例证明目标函数为何不能只看阶段数。主要服务 RQ1。

### 3.1 固定路径资源模型与执行语义

定义端点、资源集合、每对固定路径、资源带宽与单向传播；路径信息预处理，阶段字节沿资源聚合。给出当前容量近似 `阶段时间 = 最大活动路径传播 + 最大资源聚合字节/带宽`，明确不是精确逐流时间；完整 FAST 使用原有流水线递推，不额外加入 barrier。

### 3.2 两个独立的优化缺口

小例 A 使用原生任意匹配造成碎片、较大系数策略减轻碎片的案例，同时保留“大系数反而多一阶段”的反例，说明贪心并无全局保证。小例 B 使用相同 K/q、同资源总字节的独立 WAN 组合，展示端点代理无法识别的序列化差异；两者分图呈现，不混为一个原因。

### 3.3 竞争关系与目标

用两 DC 解析族展示集中 WAN 与分散 WAN 的转折，解释为什么容量并行与重复传播成本必须联合考虑。用“累计资源工作量最大值”作容量松弛下界，注明它忽略传播、匹配和机内依赖、未必可达；目标是改善完整操作时间，并独立约束/报告规划成本。

**已有证据**：动态小例报告中的精确计划、两 DC 公式和守恒检查。固定路径总字节不变的结论仅用于路径映射确实保持不变的比较；完整 GPU 流水线若重分配发送位置，必须按实际 payload 重新核验。

**过渡**：目标是保留分解的有效粒度，同时改变代理目标无法区分的资源组合；由此引出方法的受保护决策空间。

## 4. Bounded Resource-Aware Decomposition（有界资源感知分解，约 1000 词）

**目的**：完整回答算法在哪一步利用拓扑、允许改变什么、复杂度与保证是什么。主要服务 RQ2。**本章是待冻结设计的写作位置，不代表新算法已完成。**

### 4.1 静态资源编译与真实需求分离

描述预存每对通信路径资源 ID、容量和传播参数，在线复用；辅助矩阵仍用于可行分解，拓扑评分只聚合真实可发送字节。解释静态路径可缓存但阶段共享负载随匹配变化，不能用独占边时长之和替代共享资源评价；静态时间矩阵失败结果可作为对照，不默认并入主方法。

### 4.2 粒度约束下的拓扑匹配规则

最终需明确阈值如何选、资源信息怎样进入匹配生成、如何处理尾部以及预算耗尽时如何回退。当前 S1 最大瓶颈可作基础与消融，等 q 两阶段交替环只能作已验证原型；它跳过大量 Zipf 异 q 窗口，不能提前称为最终统一算法。这里预留一份主伪代码，而不是写多个策略名后用实验挑最好结果。

### 4.3 正确性、成本与执行模型集成

证明每轮匹配合法、提取系数是实际最小残量、真实字节精确交付以及算法终止；区分全局证明与局部接受条件。给出包含阈值查找、匹配、资源评分和阶段次数的实际复杂度，分别报告一次性预处理和在线成本；完整 FAST 的接受目标需涵盖受影响的 dispatch/网络重叠，不能直接沿用网络阶段和的局部非退化结论。

**已有证据**：完整分解 C++ 回归、q/Z/最大度统计、等 q 交替环的窗口守恒与实际 min 检查。

**必须补齐**：最终异 q/一般残余规则；可复现 C++ 规划成本；完整流水线对接。若只能支持受限子场景，应缩小标题和贡献范围，而不是隐藏条件。

**过渡**：给出算法及其保证边界后，评估须同时检验通信收益、算法成本及机制预测，而不是只给最大加速。

## 5. Evaluation and Discussion（实验评估与讨论，约 1000 词）

**目的**：回答 RQ3，验证 RQ1、RQ2 的因果解释。正式主结果用方向冻结后尚未用于调优的新需求/种子，现有 pilot 标为开发与机制证据。

### 5.1 统一实验设置与主要对照

完整主对照是 FAST-native（scaling 开/关分列）与 GPU 级 spreadout-like，共用真实需求和物理评价；独立 BvN 网络阶段和只用于机制消融，不冒充完整操作。拓扑从多 DC 固定路径出发，以独立 WAN 对、集中网关和多级共享上联区分共享结构；负载覆盖严格均匀、微扰均匀、不同 Zipf 倾斜、每源字节与端点放置，实际数据未提供前不写真实 MoE 结论。

### 5.2 总体效果、消融与机制归因

分别画完整通信时间、规划 CPU 与阶段数；核心消融为“原生/改进粒度 × 无/有资源感知”，S2/S3 作为辅助比较，不按输入挑选最佳策略后冒充单算法。分解序列化项与传播项、对照资源总字节；保留均匀无改善、Zipf 输给 spreadout-like 和 S1 阶段增多的情况，以检验收益来源而非追求全胜。

### 5.3 适用域、成本与局限

通过带宽比、传播差、每源负载及规模，检验两 DC 转折和组合机制是否解释实测仿真趋势；机制控制与代表性面板分开统计。规划报告重复样本、预处理摊销假设及必要的“规划+通信”串行预算，不把模型值冒充实机墙钟；讨论固定路径、阶段模型、有限拓扑族和合成负载的限制，加入独立路径与共享路径解析检查及可行的模型敏感性控制。

**已有证据**：规模、静态与组合 pilot 可支持实验设计和机制图。它们尚不能替代正式强基线、最终算法及独立验证集。

**过渡**：从“何时、为何、代价多大”回到研究问题，只将被完整验证的结论带入结论章。
