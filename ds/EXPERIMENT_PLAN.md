# 独立部分分解算法异构拓扑实验设计（第一轮，已执行）

日期：2026-11-10。范围：只研究仓库内独立的部分分解模拟器；不接入真实流量记录，不做与原系统合并后的端到端实验。所有比较使用同一份输入需求、同一编译产物和同一套解析阶段评价器。

工作区约定：实验生成、运行、审计脚本和临时修改都放在本目录；不改生产代码，不覆盖历史归档。本轮数据与结果见 `RESULTS_FIRST_ROUND.md`。

## 1. 只回答一个问题

当前主线是仓库内的独立部分分解模拟器：

- 输入为若干端点、固定单路径拓扑和原始字节需求。
- 不做原系统的流量均衡与任务分发，不做机内重叠，也不补齐为双随机矩阵。
- 允许不完整匹配、真实字节残余和逐阶段独立评价。
- 报告的阶段时间总和是解析阶段代价之和，不是原系统合并后的端到端时间。

原有完整分解方法和所有部分分解预设都在同一个拓扑评价器下计费。这里的“原有完整分解方法”只调用原实现的补齐和分解两步，不调用原系统的流量均衡与任务分发，也不包含机内重叠；它是同评价器下的分解基线，不是完整原系统基线。因此本实验回答：**分解、匹配、阶段划分和拓扑代价**是否改善解析完成时间，以及代价在哪里；不回答合并后的端到端时间。

## 2. 正确性门槛

正式矩阵前先跑人工小例；数据在 `experiments/raw/smoke/`，审计在 `experiments/audit/smoke_audit.json`。

| 小例 | 输入 | 检查 |
|---|---|---|
| 单端点空需求 | 一个端点，没有需求 | 空计划、零时间、无除零 |
| 单条流 | 1024 字节，100Gbps，单向传播 5 微秒 | 5.08192 微秒，一个阶段 |
| 共享瓶颈的两条流 | 两条各 1000 字节，共用一条 100Gbps 有向资源，传播 5 微秒 | 合在一个阶段约 5.16 微秒；人为拆成两个阶段约 10.16 微秒 |
| 独立路径的两条流 | 需求同上，但两条路径各有 100Gbps 独立资源 | 约 5.08 微秒；资源编号没有混用 |
| 三端点稀疏需求 | 一条 1 字节流、一条 2 字节流，含空端点 | 部分分解不补齐、不预设阶段数；守恒 |
| 同一稀疏需求、统一共享资源 | 三端点稀疏需求，所有路径共享同一资源 | 真实字节、阶段结构与资源使用一致 |
| 非均匀三端点拓扑 | 六条有向路径带宽为 100Gbps、1Gbps、10Gbps、1000Gbps、100Gbps、5Gbps，单向传播为 0、5、1、0、2、10 微秒，需求含 1 字节尾部 | 每对守恒、有限轮终止、误差报告 |
| 无完美匹配的支持图 | 只有 0→1、0→2、1→2 三条方向有需求，三端点无法形成完整置换 | 部分分解继续工作；补齐量不混入真实服务字节 |

每个正式运行还通过：

- 输入非对角字节总和等于报告的需求字节数。
- 逐源、逐目的重放等于输入需求；真实字节模式允许零误差，时间计价模式使用每个端点对 1e-6 字节的工具容差。
- 每个阶段每个源、每个目的至多一条流；无自环；字节为正；真实字节模式为整数。
- 报告的总阶段时间、串行化时间之和、传播项之和分别等于各阶段对应值之和。
- 每个阶段满足“最大单向传播时间加最大资源串行化时间”的公式。
- 每资源总字节与按输入路径独立重放的结果一致；不同计价方法之间资源总字节在声明容差内一致。
- 同一场景的五个预设共享相同需求字节；重复三次的计划由工具内部重复构建，规划时间样本只用于波动估计。

审计脚本不调用模拟器；它解析原始输出格式并独立重放。第一轮 58 个场景、290 个运行的审计结果为 0 个错误。

## 3. 第一轮场景

采用测试矩阵文档中的五种拓扑和三种正式流量。

- 全互联专用链路、双数据中心网关瓶颈：16 个端点。
- 四数据中心标准分层、四数据中心出口/入口窄口、四数据中心长传播：32 个端点。
- 每端点发送预算取 8MiB 或 128MiB；总需求等于端点数乘预算。
- 生成单位为 1KiB；所有输入都是 1KiB 的整数倍。原有完整分解方法接收 1024 字节单位，部分分解预设接收 1 字节单位，两者收到相同真实字节。
- 均衡全通信：每一行、每一列都等于每端点预算。
- 接收端齐夫倾斜：目的地按排名取权重，排名第 r 的目的地权重为 r 的 -0.9 次方；每个源排除自身后归一化到预算，再用最大余数法取整到 1KiB。随机种子为 11、23、47。
- 热点数据中心成组：只用于 32 端点、四个数据中心、每数据中心 8 端点的拓扑。热点比例取 0.8，随机种子为 11、23、47。采用测试矩阵文档的“两组完整置换”读法：每个源向热点数据中心发一条热点流，向冷点数据中心发一条冷点流；源数据中心内的槽位通过完整置换映射到目标槽位。每个目标槽位各收到来自热点源组的一条流和冷点源组的一条流，因此所有行、列之和严格等于每端点预算，且每源只有两条流。热点预算取整到 1KiB，余下为冷点预算；实际热点比例约为 0.7998 和 0.79999。

名义规模：

```text
均衡全通信：5 种拓扑 × 2 种规模 = 10
接收端齐夫倾斜：5 种拓扑 × 3 个随机种子 × 2 种规模 = 30
热点数据中心成组：3 种拓扑 × 3 个随机种子 × 2 种规模 = 18
合计 58 个场景 × 5 个预设 = 290 个运行
```

热点数据中心成组的不同随机种子仍按输入矩阵的校验值去重。当前 18 个场景实际只有 6 个不同需求矩阵：同一个种子、同一种规模的矩阵在三种四数据中心拓扑间复用；种子改变热点位置；不同种子还可能因数据中心和槽位对称给出相同的部分分解代价。报告不把这些条目当作独立统计样本。

第一轮预设：

| 名称 | 配置 | 作用 |
|---|---|---|
| 原有完整分解方法 | 只调用原实现的补齐和分解，不调用流量均衡与任务分发 | 同一评价器下的分解基线，不是完整原系统基线 |
| 部分分解端点基线 | 真实字节；不补齐、无候选、无局部编辑；每轮只做普通匹配 | 分离“取消补齐、允许部分匹配”本身的影响 |
| 拓扑感知贪心 | 先比全局压力评分，压力打平时再比局部阶段总时间；启用压力候选和删除、插入、交换三类编辑；候选上限 8，编辑上限 32，种子真实服务量至少保留 50% | 当前主策略 |
| 序列化时间映射 | 以序列化时间计价，路径权重为 0.008 除以最小带宽 | 观察序列化时间计价的影响 |
| 传播修正时间映射 | 以序列化时间加传播项计价，路径权重为 0.008 除以最小带宽再加单向传播除以字节 | 观察传播修正计价的影响 |

第一轮不扫描候选预算、编辑预算、种子保留比例、传播修正系数或延迟系数，不逐场景选最优参数，也不用验证集调参。

## 4. 指标

主指标：阶段时间总和。配对加速比为：

```text
加速比 = 基线阶段时间 / 本方法阶段时间
```

同时报告相对原有完整分解方法和相对部分分解端点基线的加速比、阶段数、候选评估与修改次数、串行化时间之和、传播项之和、规划时间中位数、每资源总字节。平局容差固定为相对 1e-9，不因结果调整。汇总按拓扑、流量和规模分组，保留最差退化和所有负例，不只报总几何平均。

## 5. 第一轮之后

已验证第一轮信号；下一步只做有假设的消融，按单因素或少量交互，不跑全笛卡尔积：

1. 拓扑组件：只用压力评分、只用局部编辑、两者同时使用。
2. 全局评分：不用全局项、最大残余、平滑残余、压力评分；局部固定为阶段总时间。
3. 局部评分：不用局部项、阶段总时间、平方工作量、最大路径时间；全局固定为压力评分。
4. 预算：候选上限取 2、4、8、16，编辑上限取 8、16、32、64，记录规划时间。
5. 传播与时间的隔离：增加“固定真实字节分解、仅用序列化时间或传播修正时间计分”的对照，区分计价本身与分解轨迹变化。
6. 热点数据中心成组若需要测试“热点组加碎片化”，另立块均衡或扰动置换流量，并单独命名，不能与当前两置换写法混称。
7. 双边齐夫倾斜和稀疏循环置换混合流量按测试矩阵作为第二轮扩展。

- 探索使用随机种子 11、23、47。
- 配置、预算、种子保留比例、传播修正系数、延迟系数、平局容差和汇总脚本冻结后，才使用验证随机种子 101、103、107、109、113。
- 探索集和验证集分表报告；不能根据验证集逐场景选方法再称为在线算法。

## 8. 中止条件和开放问题

遇到以下情况先修工具或模型，不扩大扫描：

- 审计失败、资源总字节随方法变化、非有限或负流量、重复源或目的。
- 同一输入重复运行产生不同计划，已声明的跨构建无序集合风险除外。
- 全互联专用链路上，拓扑感知方法和端点基线出现无法由阶段数或字节解释的巨大差异。
- 规划时间随端点数增长到不可接受，而收益没有同步增长。

持续保留的开放问题：

- 平方工作量和压力评分都是局部启发式；可以严格改善首阶段却恶化完整计划，实验结果不宣称全局最优。
- 带宽感知只优化串行化时间；完成时间感知是静态总时间启发式，不是包级网络真值。
- 模型是“最大传播时间加最大资源串行化时间”的解析近似；独立路径会出现排序反转，结论限定在该模型内。
- 部分分解的序列化时间预设和传播修正预设会改变加权残余轨迹，不只是改变阶段计分；若要隔离计价影响，需要新增固定分解的对照。
- 默认不带拓扑评价的原有路径仍保留历史自环语义，本实验不拿它作干净基线。
