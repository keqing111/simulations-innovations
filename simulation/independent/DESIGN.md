# 两条独立的 FAST 拓扑策略

2026-11-02。用户要求回到共享带宽与完成时间两个方向，分别实现、验证，暂不组合。

## 范围和实现选择

仅新增本目录，不修改其他 agent 正在批注的工作树源码。编译依赖固定 `planning/results/final-96b18da3da36/source`，先逐文件验证摘要，保持原生 balance、dispatch、补齐、扣减和 pipeline2。不使用 ns-3，不改变路由，不新增 barrier，不将单次解析计时称为实测网络。

原始需求仍是字节。每轮先取得原生匹配；可选对照用已有 Max-Min 求 q* 种子。以下策略的候选都限制在 A>=q 的支持图内，候选最小系数必须等于该轮种子系数，真实跨服务器服务字节不得少于种子。否则回退种子。此局部系数保护不保证后续总阶段数相同。

- `native`：不改原生匹配。
- `bandwidth`：原生种子；复用冻结 ResourceCache 的一次共享资源引导增广构造，仅当候选的最大共享资源串行化时间严格降低才接受。候选与验收均不以传播时间排序。预编译资源等预处理计入规划。
- `time`：原生种子；按本轮真实字节 x 构造辅助边代价 alpha+0.008*x/min_path_bandwidth，自环/零真实量代价为0；在 A>=q 支持图上，用费用阈值二分与增广路求最小最大单路径完成时间匹配。仅当前目标严格降低且满足上述服务/系数保护才接受。它不累加其他并发流的共享资源竞争；这是独立的时间导向策略，不是联合算法。
- `maxmin`、`maxmin-bandwidth`、`maxmin-time`：同一组策略使用已有精确 q* 种子，分离粒度收益。
- `spreadout`：GPU 循环偏移基线，共用完整资源计价，不冒充完整 NCCL。

辅助时间矩阵每轮根据真实剩余量与 q 更新，不替代字节需求，不将 RTT 与串行化相乘。时间策略精确最小化当前支持图的最大边代价，不能声称最小化整个 A2A。

所有方法最终均用原有 Topology::evaluate 的最大活跃路径传播+最大资源服务时间及原生 pipeline2 计价。时间策略的单路径预测和共同评价器明确区分，不能通过换计时公式显示收益。

## 选择理由

选择在既有引擎的 hook/decompose_with 中实现，较改动原生全局代码更易隔离并行批注；时间策略选择阈值增广匹配，避免枚举排列或引入通用求解器。先做纯串行化修补/单路径时间两条独立路线，而不是直接联合评分，以便解释增益与代价。
