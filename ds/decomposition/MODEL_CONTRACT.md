# 与现有仿真一致的调度优化模型

2026-11-12。目标是让可行域、状态更新、评价函数与当前显式Topology/pipeline2仿真对应，不增加真实网络细节，也不修改计价以制造收益。本文件定义优化问题，不宣称某个启发式已求得其最优解。

## 1. 先固定三个部分

1. **状态**：辅助残余矩阵R、真实GPU待发数据Z，以及上一阶段尚需dispatch的时间d。
2. **动作**：合法完整匹配P及其实际提取系数q。
3. **目标**：原生流水线输出的完整操作时间，而不是阶段数、流量推进量或资源价格。

资源价格只能是求解这个问题的工具，不是另一个未经解释的物理目标。以下只考虑静态单路径、显式Topology入口、同构机内参数；不将默认非Topology旧自环行为混入本模型。

## 2. 输入和可行性

给定真实GPU需求、固定路径/资源容量/单向传播，以及原生scaling开关和判据。原生构造与balance决定的预处理固定，得到：

- f：本次分解固定的缩放因子，关闭时为1。
- R0：对缩放后的server代表矩阵进行原生补齐所得辅助矩阵。
- Z0：balance后的真实GPU需求状态；必须保留目的GPU信息，不能只存server总字节来计算dispatch。
- B、H：原生机内模型得到的一次性balance时间与intrinsic时间，单位us。

每轮在R的正支持图上选择完整置换P，q为所选残量的实际最小值。辅助更新 `R' = R - q*P`，网络阶段容量换回原单位为f*q。

真实状态按Local的确定性dispatch规则更新：`(Z',x,D) = Dispatch(Z,P,f*q)`，其中x是每GPU真正发送的量，D是本轮dispatch时间。每源GPU到所选目的server的发送量为剩余需求与阶段容量的较小值；目的GPU细分及搬运计时沿用原代码。补齐容量和自环不产生新增真实跨机流量。

每轮至少消去一个辅助正项，辅助残量非负，且所有真实跨机字节最终交付。终止条件是辅助分解结束并核验真实剩余跨机需求为0，不是达到某个经验阶段数。

**S1限制是另一个明确的可行域选择**：如要求每轮q等于当前最大可行瓶颈q*，就在上述动作集合中增加该限制。它不保证所有完整分解中的全局最优，更不保证未来阶段数不增加。

## 3. 阶段网络模型：完全复用Topology计价

令x是本阶段真实GPU流量，按固定路径汇总到有向资源：

```text
L[e] = 本轮所有经过资源e的真实字节之和
S    = max_e (0.008 * L[e] / B[e])              # B单位Gbps，S单位us
A    = max_活动真实路径 (单向传播us)             # 没有真实流则为0
I    = A + S
```

这正是 `Topology::evaluate_gpu()` 的阶段计价，不是精确逐流完成时间。反向WAN资源独立；RTT不另收一次；虚拟流量不计费。传播最大值与资源最大值可能来自不同流，属于既定容量近似，不将它重新解释为包级准确模型。

静态缓存的是路径关系和容量。L取决于当前P、q和Z，不能用固定独占边时长替代共享聚合。资源工作量具有时间量纲，可直接进入阶段代价；不采用字节乘RTT之类混合量纲。

## 4. 总体目标：严格对齐pipeline2

非空分解有K个阶段，网络时间为I0..I[K−1]，机内dispatch为D0..D[K−1]：

```text
J = B + max(H,I0)
      + sum(k=1..K−1) max(D[k−1],I[k])
      + D[K−1]
```

K=0时J=B+H。全部D=0、B=H=0的论文反例中，才可简化为J=sum(I)。不能把这个特殊简化推广到任意GPU需求。

J是优化的唯一通信目标；K、传播和、序列化和、利用率代理仅用于解释。规划成本另外测量并报告；若以在线延迟为目标，应明确预算或串行/摊销假设，不随意加一个权重把CPU与通信混在一起。

## 5. 当前阶段最优为什么仍可能整体变差

定义状态z=(R,Z,d)，d为上一轮dispatch（初始d=H）。完整问题可等价写为：

```text
V(z) = min_合法动作(P,q) [ max(d,I(z,P,q)) + V(z') ]
z'   = (R',Z',D(z,P,q))
V(终止状态) = d
初始总目标 J = B + V(R0,Z0,H)
```

这是对原有流水线的数学重写，不是要求在线运行动态规划。完整V的精确搜索可能很大，不纳入在线算法。

当前资源定价版本实际优化的是I这一阶段子目标，忽略了V(z')。即使将I求到全局最小，也不能据此证明J下降。它的三个退化案例不能仅靠“价格没调好”来解释；未来真实状态确实是总体目标的一部分。

因此，后续任何局部评价都必须声明其含义：若只使用I，就是即时贪心；若使用 `max(d,I)+V_hat(z')`，V_hat必须是明确的剩余完成时间近似（单位us），而不是未解释的“压力分”。剩余资源工作量下界可用于核验，但下界很接近不表示未来实际成本接近，不能默认它就能正确排序。

## 6. 什么叫在仿真下可靠

| 检查 | 必须满足的条件 |
|---|---|
| 可行性 | 每轮完整正匹配、q为实际min、整数辅助重构与真实交付守恒 |
| 状态一致 | 模型的Z更新和Local实际payload一致，包含GPU细分及缩放容量裁剪 |
| 阶段一致 | 独立资源汇总与Topology的I一致，浮点仅采用声明容差 |
| 总体一致 | 按上述J重算与Global输出一致，包含首项、末尾dispatch和K=0 |
| 优化主张一致 | 当前阶段改善、窗口改善与全局改善分别表述，不混为一个保证 |
| 求解界限 | 仅有有效下界与可行解相遇等证据才声明全局最优；停滞不等于局部最优 |

前三类已有反例和开发面板核验，但不能据此称所有可能GPU需求均经过穷尽验证。后续新增状态近似或求解规则后需重新做对应检查。

## 7. 接下来只解决一个问题

先在CE-1和已知退化案例中，对照“即时I更小”与“后续实际完成代价更大”的分歧，固定同一前缀状态进行回放。小规模精确计算仅作离线核验，不用于在线枚举；大例先用确定性参考后缀诊断，不冒称真实最优V。

据此选择一个简单、可解释的V_hat，或者选择能保持窗口后状态相同的受限优化域。前者有近似误差，后者有覆盖率限制，需要明确取舍，不能同时承诺普遍覆盖、极低开销和全局最优。

现阶段不再添加新价格公式，也不重定义网络模型。优先让优化目标、近似对象和仿真输出形成可核验的一条链。
