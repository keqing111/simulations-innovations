# 固定路径异构网络上的资源感知 A2Av：当前算法与实验边界

## Material Passport

- 日期：2026-11-15；本报告为工程研究交接，不是论文定稿。
- 已完成结果来自SimAI/ns-3；新异构拓扑的效果仍须单独测量。
- 研究对象是固定路径下的匹配与分解，不优化路由、不模拟GPU计算波动。

## 1. 算法依据与实际流程

端点满足“一发一收”不代表物理网络无争用：多对服务器仍可能共用一条上联。反过来，存在多条独立资源时，把工作都放到少数链路上会浪费并行能力。因此我们保持BvN的合法分解框架，但用路径资源关系指导哪些通信对同轮执行。

静态输入为通信对的固定有向资源列表、各资源带宽和整路径单向传播时间。真实需求`U`与辅助等行列和矩阵`R`分离，不把数据量乘RTT，也不发送补齐的虚拟字节。

```text
真实残余U → 各资源剩余字节/带宽与端点压力
正残余R → 求最大可行系数 q*（最大化匹配边的最小残量）
保留合法q*参考匹配 → 以共临界资源/端点代表边构造资源预算匹配
比较本轮与剩余完成时间代理 → 时间目标全平局时保留参考
扣减R，按min(q*,真实通道残量)发送 → 下一轮重新计算压力
```

主要计价均使用时间单位，不能混合“字节”和“时间”直接相加：

```text
资源剩余工作 L[r] = 需经过r的真实残余字节 / B[r]
本轮资源负载 V[r] = 所选通信对经过r的实际发送字节之和
本轮时间代理 = max_r(该资源上的最大整路径传播时间 + V[r]/B[r])
```

一个通信对经过多个资源时，对每个资源登记容量占用，真实交付仍只计一份。依赖前沿另外近似接收信用、发送槽和ACK释放；实际执行由ns-3事件决定，不把代理时间写成流启动时间，也不增加全局stage barrier。

匹配构造使用资源压力直接选边；SCC与交替环只负责维持“已选边还能补成合法完整匹配”，不是用交换预算反复搜索完整分解。每轮采用实际最大系数，至少一条辅助边归零，保持非负残余和完整重构。它不保证全局最少轮数或最小完成时间。

## 3. 当前证据与限制

旧4DC均衡机制中，相同31轮、同系数序列和同总字节，仅改变同轮匹配，纯MaxQ的9.692ms降至4.568ms，约2.12×。这是资源并行利用的证据，不是减少流量或轮数。

扩展27条件（24新条件＋3参考）后：相对FAST-SimAI为2.986×，相对Spreadout为1.085×，相对纯MaxQ为0.99993×，分别为27/0、21/6、12/15胜负。说明整套方案有收益，但拓扑选择的增量在这些真实层/窗口和Zipf种子中尚不稳定。所有Zipf条件都慢于Spreadout，负结果保留。

以上只计完整通信时间，不含规划。当前Python核心CPU约64GPU下0.15–0.33s、96GPU下0.67–0.81s、128GPU下1.4–9.2s，不能宣称在线开销已解决。阶段估计不是精确DCQCN预测，也不保证本轮更优就全局更优。

旧算法已经对全部物理路径资源计价，但部分分组覆盖优先级依赖WAN标签。异构扩展应显式指定共享交换资源，保留旧默认行为作对照，不能只给普通链路改一个WAN名字。

## 4. 拓扑×负载实验

机器布局不变：每server4GPU、每ToR4server。固定唯一路径，速率采用现有DCQCN配置支持的100/200/400/1600Gbps；机内模型不变。

| 拓扑 | 规模与差异 |
|---|---|
| `leaf-uniform` | 64/128GPU，4Spine，每ToR四条400G上联，单向700ns，对照 |
| `leaf-bandwidth` | 同结构，各ToR四上联按机架为400/200/100/400G，时延不变 |
| `leaf-delay` | 同构容量，机架交换上联单向700ns/2us/5us/700ns，纯时延消融 |
| `multi-cut` | 64GPU，四机架组挂汇聚链，关键割边100/200/100G，受控机制 |
| `pod-core` | 128GPU，4Pod，各Pod双ToR双Agg接双Core，上联每条400/1600/400/1600G |

| 负载维度 | 配置 | 控制原则 |
|---|---|---|
| 分布 | 严格均衡、Zipf0.8、Zipf1.2；固定新种子3101/3102/3103 | 合成输入每rank总字节相同，只改变目标倾斜 |
| 算子规模 | 每rank约1/4/16MiB（整数块粒度记实际值） | 不是每个通信对的字节；放大规模不等于背景利用率 |
| 真实输入 | DeepSeek/Llama/Kimi的独立窗口、代表层，token/GPU沿用64 | 测量的是专家选择，来源GPU和部署仍为模型假设 |
| 背景压力 | rho=0/0.3/0.6 | 独立RDMA背景；按固定路径最忙共享资源的配置负载归一化，不把rho当实测利用率 |

不一次运行全部笛卡尔积：先做`pilot`，同构/带宽异构/时延异构×3分布×1/4MiB，64GPU，seed3101、rho0，共18条件×4方法=72回放。通过交付/路径校验后，再分别扩大规模、加背景、接真实输入。其它阶段配置保存在`experiment_matrix.json`，不能把计划项标成已完成。

对照统一为FAST-SimAI、Spreadout、Volume-MaxQ和资源感知MaxQ。所有方法同输入、固定路径、信用/ACK协议与拥塞配置。主要指标为完整算子时间；同时记录规划CPU、阶段系数/轮数、资源峰值、PFC及实际释放错位。多种速率下不使用旧统一100G分母的legacy利用率。

原始采样数据、凭据、可执行文件和大体积包轨迹不推送；汇总、图表、来源摘要、脚本与ns-3源码增量随分支保存。
