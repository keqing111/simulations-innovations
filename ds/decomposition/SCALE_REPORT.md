# 均衡与规模扩展：8—64端点

日期：2026-11-11。原始输出：[scale-results-20261111/summary.json](scale-results-20261111/summary.json)，运行元数据含源码与二进制校验。共112份输出，每份3次规划，已逐轮重构与守恒检查。所有策略B=8、scaling关闭，单个合成Zipf种子101，属于规模初测。

本次与第一轮的区别：固定源端预算。直接矩阵每源9765KiB，保证能被7/15/31/63整除，严格均衡无需取整；扰动均衡在每行完整循环置换上额外加1KiB，每源9766KiB，扰动约0.01024%。GPU实验G=4，每GPU跨server预算39060KiB，先排除同server目的再分配，均衡与Zipf均固定该预算。跨规模总量随端点数线性增加，非固定总字节的强缩放实验；不与旧固定单元256KiB的绝对时间直接混表。

S0原生Kuhn，S1最大瓶颈，S2最大消边，S3最大度下降；均使用同一原生补齐规则。

## 1. 严格均衡没有阶段数优化空间

| N | 所有策略阶段数 | S0 CPU ms | S1 CPU ms | S2 CPU ms | S3 CPU ms |
|---|---:|---:|---:|---:|---:|
| 8 | 7 | .015 | .012 | .023 | .014 |
| 16 | 15 | .090 | .063 | .174 | .087 |
| 32 | 31 | .651 | .505 | 1.600 | .786 |
| 64 | 63 | 7.216 | 4.783 | 18.486 | 7.932 |

每行有N−1条正边，故至少需要N−1个完整置换。严格相等的非零单元使每轮选中边都同时耗尽，四种方法均达到这个下界。S1的同阶段CPU较小可以来自有序邻接与原生unordered访问的实现差异，不是阶段数收益；小CPU差别不凭3次样本作稳健排名。

## 4. 适用结论

- 严格均衡：优先研究相同最小阶段数下如何组织拓扑资源；继续优化K本身没有空间。
- 微扰均衡：分解粒度鲁棒性是主要问题，原生大量碎片可被轻量阈值策略抑制。
- Zipf：S1仍有明确优势，不需要把课题限制到均衡场景；但大规模CPU绝对开销必须约束。
- 当前scaling关闭是为隔离匹配策略，不能据此宣称战胜开启原生scaling后的FAST在线开销；下一轮应单独验证scaling与匹配策略的交互。
- 本轮只有固定合成种子，N≤64是当前实现边界，没有扩到更大也不声称规模普遍性。
