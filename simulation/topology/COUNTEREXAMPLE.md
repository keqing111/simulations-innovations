# 原生 FAST 的共享 WAN 匹配缺口：可手算、可重放的反例

日期：2026-11-02。用途：论文问题分析章节的构造性证据，不是新一轮算法性能确认集。

本次仅新增本文档及[证据数据](counterexamples/2026-11-02/evidence.json)，不修改正在批注的 C++、既有实验结果或原生调度语义。

## 1. 要证明的命题，以及不证明什么

**本例证明：在含共享 DC 间链路的固定路由网络中，固定公开版本 FAST 的服务器级无权匹配分解，可能输出端点完全合法、阶段数已最少、却具有更高通信完成时间的方案；存在保持需求、阶段数、阶段系数、路径、机内费用及每阶段传播项不变的合法重配方案，消除其中一部分损失。**

准确的不足不是“FAST 完全不考虑拓扑”，也不是“没有解决端点 incast”，而是：

> 原生匹配根据正残余支持图寻找一发一收配对，却不使用流所经过的中间共享资源及其容量，因而不能区分端点同样合法、但共享链路竞争不同的匹配。这个缺口会使少数阶段的共享 WAN 服务时间集中，增加逐阶段瓶颈时间之和。

这里的比较沿用原生阶段/机内流水递推，并统一增加共享资源评价。它是新增网络约束下的解析模型结论，不是对原论文适用假设下结论的否定，不是论文或代码有算术错误的证明，不是真机、ns-3 队列或任意 rank 异步运行时的测量。

不主张替代方案全局最优、不主张所有编号/工具链都产生相同坏调度，也不将本例用于证明优化算法在整个负载族中的平均收益。单个反例足以否定该扩展场景下的普遍最优性，但不足以证明实际发生频率。

## 2. 固定原生算法与实现证据

本次直接从公开原始提交 `0712d29fb13a09962425c8a57b951b91d8fc33ba` 导出 `simulation/algorithm/`、链路配置和 `define.h`，在临时目录编译，未使用当前批注中的算法文件。

诊断入口只构造本文矩阵，依次调用：

```cpp
Matrix matrix(data.data(), 6);
FastAll2All app(&matrix, 1, ETHER400, H100, 1e-6);
app.to_scaled_doubly_stochastic_matrix();
app.decompose();
// 导出每个 p_sets[k] 的 mp[0..5] 和 get_freq()。
```

原生调用链是：`decompose -> update_edges -> hungarian/hungarian_dfs -> update_permutation_sets`。前者根据残余是否为正建邻接表，增广搜索找合法匹配；后者取匹配边的最小残量并扣除。匹配过程不读取 DC 标签、路径、WAN 带宽或已有链路占用。

原始提交编译出的五个置换、顺序和频率，与冻结适配器的 `native` 输出逐项一致。适配器使用已登记的 [run-33e58e040218](../bottleneck/results/run-33e58e040218/build.json)，不是重新编译当前工作树。原始提交、源文件 SHA256、编译器、冻结二进制摘要及完整输出存入证据文件。

因此，下面的原生置换不是手工选择的“某种可能的坏解”，也不是拓扑优化器改造出来的基线。

## 3. 拓扑、需求与计时前提

### 3.1 三 DC、六服务器

```text
DC 0: S0, S1 -- ToR -- GW0
DC 1: S2, S3 -- ToR -- GW1
DC 2: S4, S5 -- ToR -- GW2

GW0、GW1、GW2 两两连接；每个方向的 WAN 容量独立。
```

|资源/参数|固定值|
|---|---|
|服务器收、发资源|各 400 Gbps|
|每 DC 共享网关收、发资源|各 400 Gbps|
|每个有向 DC 对的共享 WAN|100 Gbps|
|DC 内每段单向传播|0.7 µs|
|WAN 单向传播|5000 µs，不是 RTT|
|同 DC、不同服务器路径传播|1.4 µs|
|跨 DC 路径传播|5002.8 µs|

同 DC 服务器间流量不经过 WAN；跨 DC 流经过源网关、该有向 DC 对 WAN、目的网关。这里没有自适应路由、超出固定容量的独立逻辑链路或新增的拥塞控制。

### 3.2 完全均衡的确定性矩阵

先用每服务器一个发送端点/GPU，消除机内 balance/dispatch 对反例的干扰。令 `B=100,000,000` 字节，即十进制 100 MB：

```text
       d0 d1 d2 d3 d4 d5
s0      0  B  B  B  B  B
s1      B  0  B  B  B  B
s2      B  B  0  B  B  B
s3      B  B  B  0  B  B
s4      B  B  B  B  0  B
s5      B  B  B  B  B  0
```

每个服务器发送、接收均为 `5B`；全矩阵 `30B=3,000,000,000` 字节，其中跨 DC 为 `24B`，同 DC 跨服务器为 `6B`。这不是 Zipf、随机种子、热点或故意不平衡输入。

每行和、列和已经等于 `5B`，因此**不需要补齐任何虚拟容量**；关闭 scaling。匹配系数始终为 `B`，本例不涉及整数取整、虚拟自环、数据膨胀或原生边界缺陷。

每个服务器有五个不同目的端点，每个 stage 最多选择一个目的端点，因此至少需要五个 stage。以下两个方案恰好都是五个：原生方案已经达到该配对约束下的最少阶段数。

### 3.3 网络时间和流水线

对 stage `k`，采用既有共享资源模型：

\[
I_k=\max_{(s,d):x_{sd}>0}\alpha_{sd}
  +\max_e\left(0.008\frac{L_{k,e}}{C_e}\right).
\]

`L` 为字节，`C` 为 Gbps，结果为 µs。每轮存在真实 WAN 流，所以传播项均为 `5002.8 µs`。WAN 传 `B` 需要 `8000 µs`，传 `2B` 需要 `16000 µs`；网关最多承担 `2B/400Gbps=4000µs`，服务器为 `B/400Gbps=2000µs`，因此每轮确由 WAN 决定串行化项。

这里各真实 WAN 路径传播相同，最大传播与最大串行化对应路径不同的问题不会影响该差值。

一个端点/GPU 时，balance、intrinsic 和 dispatch 均为零，原生 pipeline2 递推退化为 `T=sum I_k`。没有为构造反例另加 barrier，也没有把原生阶段规则改成新的执行器；但这仍是阶段解析计时，不能冒充逐流完成事件或无阶段等待的实机结果。

## 4. 原生实际输出与合法替代方案

置换写成 `[d0,d1,...,d5]`，第 `s` 项表示服务器 `s` 的目的服务器。每行都是 0..5 的置换，无自发、无重复目的；每条选中边真实传 `B`。

|stage（从0计）|固定原生 FAST|合法替代方案|原生最大 WAN 字节|替代最大 WAN 字节|
|---|---|---|---:|---:|
|0|`[2,0,1,5,3,4]`|`[2,0,1,5,3,4]`|B|B|
|1|`[1,4,5,0,2,3]`|`[3,4,5,0,2,1]`|2B|B|
|2|`[5,3,0,4,1,2]`|`[1,5,4,2,0,3]`|B|B|
|3|`[3,5,4,2,0,1]`|`[5,3,0,4,1,2]`|2B|B|
|4|`[4,2,3,1,5,0]`|`[4,2,3,1,5,0]`|B|B|

替代方案由既有 `bounded` 链路修补实现实际生成，未手工修改 raw；本节只把它作为“存在更好合法方案”的见证，不主张它是全局最优或当前论文方法的最终性能。

两份置换集合分别逐项重建出上述同一个需求矩阵：每条非对角边恰出现一次；每次匹配都在正残余支持图内，扣 `B` 不产生负残余，最后清空。两者 stage 数、频率、真实发送量均一致。

### 4.1 看清 stage 1 的问题在哪里

原生 stage 1 中：

- `S4 -> S2` 和 `S5 -> S3`，端点互不冲突，但都经过 `WAN 2->1`，合计 `2B`；
- 同一阶段 `WAN 2->0` 没有流量；其他活跃 WAN 只承载 `B`。

这轮因此需要 `5002.8+16000=21002.8µs`。端点合法性没有阻止中间链路冲突。

替代 stage 1 将配对改为表中所示，六个有向 WAN 各承担 `B`，网关容量也满足约束，时间降到 `5002.8+8000=13002.8µs`。它不是凭空删掉一条需求：后续 stage 随之改变，最终完整传输全部原始数据。

### 4.2 完整 WAN 负载表

以下每个数的单位为 `B`，列顺序固定；没有列出的逻辑路径重路由。

|方案/stage|0→1|0→2|1→0|1→2|2→0|2→1|
|---|---:|---:|---:|---:|---:|---:|
|原生 0|1|0|1|1|0|1|
|原生 1|0|1|1|1|0|2|
|原生 2|1|1|1|1|1|1|
|原生 3|1|1|0|1|2|0|
|原生 4|1|1|1|0|1|0|
|原生各列合计|4|4|4|4|4|4|
|替代 0|1|0|1|1|0|1|
|替代 1|1|1|1|1|1|1|
|替代 2|0|1|0|1|1|1|
|替代 3|1|1|1|1|1|1|
|替代 4|1|1|1|0|1|0|
|替代各列合计|4|4|4|4|4|4|

两者每条有向 WAN 全程字节都为 `4B`。原生 `WAN 2->1` 的负载是 `[B,2B,B,0,0]`，替代为 `[B,B,B,B,0]`：减少了同方向需求的阶段内聚集，却**没有增加全局含 WAN 的 stage 数**。

因此，不应将现象写成“有些 stage 完全没有 WAN，因此必须强制每轮有 WAN”。本例原生每轮本来就有 WAN，仍存在共享方向上的集中与空闲；需要优化的是资源组合。

## 5. 完成时间与可归因性

令 `a=5002.8µs`，`tau=8000µs`，则：

\[
T_{FAST}=5a+(1+2+1+2+1)\tau=81.014\,ms,
\]

\[
T_{alt}=5a+(1+1+1+1+1)\tau=65.014\,ms.
\]

\[
T_{FAST}-T_{alt}=2\tau=16\,ms>0.
\]

替代方案完成时间减少约 **19.75%**，加速比 **1.2461×**。这是减少时间19.75%，不是“时间减少24.61%”。

|受控因素|核验结果|
|---|---|
|输入需求、逐服务器对交付|逐元素完全相同|
|全程逐物理资源字节|完全相同|
|总 stage / WAN stage|均 5 / 5|
|阶段系数|均为 B，五轮已经最少|
|padding / scaling|均无|
|传播项|每轮均 a，总计25.014ms|
|机内操作与费用|均为0|
|阶段执行递推与路由|相同|
|累计最大资源串行化|56ms → 40ms，是唯一时间差来源|

本例也排除了“换成 Max-Min 才得到改善”的解释：原生每轮已经扣 `B`，当前正边都为 `B`，`q*` 也只能为 `B`，粒度没有改善空间。它不排除其他遍历顺序碰巧找到更好的匹配，但说明原生选择规则自身没有对共享资源作此区分。

其代数机制是：虽然每条资源全程 `sum_k L[k,e]` 相同，`sum_k max_e L[k,e]/C[e]` 仍可不同。原生只满足端点匹配约束，不能保证后者最小。

对上表这两份固定调度，保持容量比例和有效整数范围，只改变 `B>0` 或 WAN 传播时延，差值仍是 `2 tau`：相同的五次传播项抵消。这是一对调度的参数化比较，**不是重求任意策略后也保持这些置换的算法定理**；数据很小时规划成本可能抵消通信差值，不能据此宣称含规划总收益。

## 6. 嵌入原有八 GPU/server 场景，不靠忽略 scale-up 得出结论

另对原有 `n6-g8-balanced-s0-256MiB-w5000` 归档进行了三次新重放：原生、缓存链路修补、两次受限修补；逐阶段路径和 pipeline 时间重新构造一致。

48×48 GPU 矩阵的每个非对角元素为 `c=5,711,392` 字节，GPU 对角为0；每 GPU 实际总量是 `47c=268,435,424` 字节，比名义256MiB少32字节，沿用旧归档，不改数据。服务器级每 GPU 代表量为 `8c`，每个 server 对的真实总量为 `64c=365,529,088` 字节。该均衡矩阵同样无需 padding。

|指标|原生 FAST|合法链路重配|
|---|---:|---:|
|总 stage / WAN stage|5 / 5|5 / 5|
|累计传播|25.014000ms|25.014000ms|
|累计瓶颈串行化|204.696289ms|146.211635ms|
|初始 balance|0|0|
|intrinsic 机内 A2A|89.543876µs|相同|
|各 stage 的 dispatch|每次89.543876µs|相同|
|完成时间|229.799833ms|171.315179ms|

两份调度的每段网络时间都大于相应机内操作，intrinsic/中段 dispatch 按原生规则被隐藏；末尾 dispatch 在两者中均计入。时间减少约25.45%，不是删去机内费用或改变重叠规则得到的结果。

这说明单端点反例揭示的机制可以出现在本项目原有八 GPU/server 模型中，但该归档已用于开发，不能当作新的独立确认输入。它只补强机制，不证明所有多 GPU 实现/实机运行均有该收益。

## 7. 建议用于论文的精确表述

> FAST 的服务器级匹配避免了同阶段的端点收发竞争，但没有显式约束并发流对中间共享链路的叠加负载。我们在固定公开实现及共享 WAN 解析模型中给出一个完全均衡的构造性实例：原生分解已使用最少的五个阶段，所有阶段均含跨 DC 流量，仍在两个阶段产生双倍 WAN 瓶颈负载。存在保持数据量、阶段粒度、传播项及机内流程不变的合法重配，将累计瓶颈串行化费用从56ms降至40ms，完成时间从81.014ms降至65.014ms。因此，端点匹配合法与最少阶段数并不足以保证共享网络上的最优通信完成时间。

不应写成：FAST 从不考虑拓扑；原生 FAST 发送了错误数量的数据；WAN 每轮活跃就能最优；减少瞬时队列已经被实测；我们的替代方案具有全局最优性；该单例已经证明整个多DC/Zipf负载族的普遍收益。

新方法的全局有效性、在线成本和负例，应在后续方法/实验章节单独论证，不从本反例自动推出。
