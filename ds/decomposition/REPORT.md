## 实现和边界

核心接口位于 `simulation/algorithm/all2all.h/.cpp`：新增 `DecompositionOptions`、逐轮统计、`decompose(options,stats)`；原无参数接口不变。Global增加 `set_decomposition()` 和统计getter，仍用原pipeline2的balance、server间通信、dispatch与重叠递推。实现说明见仓库根目录 `bvn_matching_implementation_20261111.md`，独立审查见 `bvn_matching_review_20261111.md`。

- S0：原生无权Kuhn，保留unordered遍历顺序，仅外侧插桩。
- S1：正残余去重排序，二分阈值，正边邻接Kuhn检验完美匹配，求精确单轮最大瓶颈。
- S2：先求S1阈值上界，再在不超过它的正残余值中按索引分位点选最多B=8个阈值；B≥2含两端，B=1只用上界。真正Hungarian最大化等于t的匹配边数，禁边不参与松弛；零目标候选跳过，按Z再按实际alpha选择。
- S3：同一有限阈值池降序试探，所有最大度行/列关联的选中边必须等于t。成功则Delta下降1，否则回退S1。

所有策略共享原生补齐、整数存储、scaling语义和实际最小残余扣减。Z与Delta是补齐后的辅助矩阵量，包括虚拟容量；不是物理网络流完成计数。新增策略本轮不使用拓扑奖励。没有部分匹配、删插交换、全局整数规划或在线枚举。

实际单轮复杂度含稠密读取O(n²)：S1为O(n²+m log m+nm log(q+1))；S2再加O(Bn³)，S3再加O(Bnm)。这里m为正残余项数、q为不同正值数。完整规划还乘以实际轮数K，不能仅凭单轮多项式就断言满足在线时限。额外工作内存O(n²)，输出O(Kn)，采样trace O(KB)。

## 数据与计时

13份直接分解矩阵：用户3×3例，以及N=8/16/32的严格均衡、1单位扰动均衡、接收端Zipf(alpha=.9,seed101)、随机加权置换和矩阵。直接例允许非零对角，因为此处验证的是辅助矩阵分解。

8份GPU输入：N=8/16，G=4，均衡/合成Zipf，分别用原生alpha-beta与三DC静态拓扑评价。构造GPU矩阵后清零所有同server块，保留真实跨server需求，避免默认旧入口的intrinsic/self-loop历史歧义。仍运行Local balance/dispatch，不是只计网络阶段。生成单位1KiB，scaling关闭；同一输入四策略配对。不同规模/分布总量不必相同，不能跨案例直接比较绝对时间。

共21输入×4策略=84份输出，每次重新构造并重复3遍。输入、逐阶段alpha/Z/Delta、完整置换、CPU原始样本与摘要均保留。脚本独立验证重构、正支持、完美匹配、实际最小alpha、每轮清零数、最大度变化和最终跨server字节守恒。

CPU来自std::clock，仅分解，不含补齐、Local工作和网络模型计算；包含必要的统计插桩开销。原生基线同样插桩，不宣称无观测成本。另报补齐墙钟、规划墙钟及构造/模型执行墙钟，三者不冒充CPU。小例CPU计时接近1us标称tick，不用于精细排名；3次样本只是初测。

运行元数据保留源码SHA、二进制SHA、编译器和revision。主agent核对最终源码哈希全部一致。未找到有来源标记的真实MoE流量矩阵，所有Zipf均明确为合成；CLI已能读取外部整数矩阵，但未虚构真实数据实验。

样例K最少为3，因为每行三个正项，每阶段最多消除每行一个；S1/2/3首轮alpha2、Z3、Delta3→2，达到3阶段。强制原生首轮取主对角alpha1的测试得到4阶段。默认S0在本环境也恰好4阶段，但不把此顺序保证推广到不同标准库。

N32 Zipf分解CPU中位数：S0 13.037ms，S1 15.093ms，S2 108.695ms，S3 21.330ms。S1明显减少K，但不必然降低CPU；S2当前阶段多且单轮贵。S3同例184轮中152轮回退S1，即约82.6%，严格覆盖所有关键端点的条件经常无法满足。它仍是有效策略，不代表消除全局最少阶段。

## 完整 FAST 流水线结果

单位ms。CPU是分解本身的3次中位数，A2A是原pipeline的预测通信完成时间；两者不同，不将进程耗时当网络仿真时间。

| N16/G4 Zipf | S0 K/CPU/A2A | S1 K/CPU/A2A | S2 K/CPU/A2A | S3 K/CPU/A2A |
|---|---|---|---|---|
| 原生alpha-beta | 214 / .849 / 1.4106 | 86 / 1.375 / 1.2393 | 105 / 7.728 / 1.2543 | 88 / 1.948 / 1.2409 |
| 三DC静态资源 | 214 / .870 / 37.3758 | 86 / 1.408 / 28.6645 | 105 / 7.900 / 28.9192 | 88 / 1.959 / 29.0160 |

这说明低延迟场景的通信节省可能小于额外规划CPU：S1原生计时只省约171us，CPU增加约526us。三DC同例通信省约8.71ms，额外CPU约.54ms，更可能具有实际价值。这是成本量级比较，不是实测网络端到端墙钟时间。

确定反例：N8/G4 Zipf、三DC评价，S0 44阶段/7.669872ms，S2 36阶段/7.991080ms。减少阶段但完成时间更差。对应最繁忙资源的容量工作量/完整A2A时间由约.438降至.421；此值是静态工作量占比代理，不是测得的链路忙闲时间线。资源总必经字节不变。

另一个反例：N8/G4严格均衡、三DC，所有策略7阶段，但S2时间5.069329ms，其他4.398241ms。相同K也不能推出相同资源组合及时间。N16/G4均衡同样15阶段时，S1/2/3反而优于本环境的S0拓扑组合。

输出中 `unhidden_intra_ratio` 是原pipeline的未隐藏机内开销比，不把1减去它称为一般流水线利用率。全零流水线时在实验JSON边界定义此比值为0，避免原默认0/0输出NaN；未更改原生递推公式。
