# FAST 两条独立策略：共享带宽与完成时间

2026-11-02。状态：实现、机制输入、小扫描、独立审查及审计修复回归均完成。本轮不组合两种策略，不修改其他 agent 正在批注的源码。

## 1. 这次到底改了什么

需求仍是字节，匹配仍在补齐后的正残余矩阵中产生，balance/dispatch/pipeline2 沿用冻结原生引擎。没有将字节乘 RTT，没有修改执行等待规则，也没有把计价器换成更有利于新方法的公式。

每轮有一个种子匹配，其最小残量为 q。新候选必须保持**本轮系数恰等于 q、真实跨服务器服务字节不少于种子**，否则回退。两种策略分别是：

1. **共享带宽策略 `bandwidth`**：在 A>=q 的支持图上，用部分匹配的共享资源占用引导一次增广构造；优先较小的资源负载/带宽峰值，再以平方增量破平局。候选最终只有在**最大资源串行化时间**严格下降时才接受，候选构造与验收均不以传播时间排序。它不是只在原生结果后修改费用，也不是本轮另做的排列枚举。
2. **完成时间策略 `time`**：每轮用真实剩余量生成该轮辅助边代价 `alpha+0.008*x/min_path_bandwidth`（字节、Gbps、us）；在 A>=q 支持图上，用费用阈值二分和增广路求**最大单路径完成时间最小的完美匹配**。它不是最大权重之和，也不把其他并发流的共享竞争加入构造目标；只有此目标严格下降且满足两项保护才接受。没有实际字节的虚拟槽位和自环代价为0。

辅助时间矩阵只指导匹配，不替代真实剩余矩阵。选定后仍扣匹配最小正残量；每轮至少清零一条正边，最多 N² 阶段。系数保护只针对当前残余，不保证全程阶段数或CCT单调改善。

`native` 为原生匹配。另有 `maxmin` 及 `maxmin-bandwidth`、`maxmin-time`，先用已有精确 q* 匹配作种子，排除原生粒度问题；这不是两条新策略的组合。`spreadout` 为GPU循环偏移对照，不冒充NCCL完整实现。

## 2. 公共评价、隔离和复现约束

所有方法统一按最大活跃路径传播+最大共享资源真实字节/带宽评价 stage，再按原生 pipeline2 组合机内费用。共享资源包括服务器收/发、网关收/发、有向DC对WAN；不模拟包队列、ACK、PFC或DCQCN。

机内 balance/intrinsic/dispatch 的内部代价复用冻结原生实现，不是另一套独立机内仿真。原生虚拟自匹配仍可能处理保留的同机数据块；本模块不将自环当WAN服务，也不声称修复该历史边界。两个机制输入不需要padding，因而不受此问题影响；一般Zipf结果只适用于所保留的原生机内语义。

编译只读取并逐文件验证 `planning/results/final-96b18da3da36/source`。当前批注代码不参与构建；不 checkout/stash/覆盖工作树，新增代码全部位于本目录。每个方法/重复重新构造Local/Global，不复用已消耗的需求。

时间策略求的是当前辅助图上的最小瓶颈，不保证整次A2A最优；最小瓶颈候选若减少真实服务量或改变本轮系数，仍会被保护规则拒绝。预处理、候选预测和trace开销均计入规划。静态拓扑视为已知输入，最终网络计价与JSON输出不计入规划。

## 3. 两个机制输入：实际策略输出，不再是手工见证

共用6服务器、DC映射 `[0,0,1,1,2,2]`、每服务器1GPU，每条非对角需求100,000,000字节。WAN单向5000us，LAN每段0.7us；无padding、无scaling，总stage均为5。

### 3.1 带宽受限：400/400/100Gbps

服务器/网关/有向WAN分别400/400/100Gbps。

|方法|完成时间 ms|WAN stage|累计传播 ms|累计瓶颈串行化 ms|
|---|---:|---:|---:|---:|
|原生FAST|81.0140|5|25.0140|56.0000|
|共享带宽策略|54.0126|4|20.0126|34.0000|
|完成时间策略|70.0126|4|20.0126|50.0000|

带宽策略只看串行化目标，但其选择也使远端阶段数减少，因此本例总改善包含22ms串行化和5.0014ms传播减少，不能把全部收益说成单一串行化改善。此前[严格相同WAN阶段数的反例](../topology/COUNTEREXAMPLE.md)仍单独保留作为机制归因证据。

完成时间策略也有收益，但不知道同阶段各路径的共享竞争，所以不能达到同样的串行化降低。这体现了两种目标的不同，不应强求某个样例只有一种策略改善。

### 3.2 时延受限：400/800/800Gbps

网关与WAN均800Gbps，足以承接每DC两台400Gbps服务器的并发，所有stage串行化均2ms。

|方法|完成时间 ms|总/WAN stage|累计传播 ms|累计串行化 ms|
|---|---:|---|---:|---:|
|原生FAST|35.0140|5/5|25.0140|10.0000|
|共享带宽策略|35.0140|5/5|25.0140|10.0000|
|完成时间策略|30.0126|5/4|20.0126|10.0000|

时间策略实际生成一个纯DC内stage及四个跨DC stage，完成时间减少约14.28%；没有增加/删除数据，也没有缩减总stage数。纯带宽目标没有改善空间，严格guard不接受候选，输出保留原生。

这支持第二个insight：原生无权匹配会将远端传播等待暴露在过多stage，而完成时间导向可以在合法约束下减少这种重复暴露。DC内stage仍是不同服务器通信，不是机内scale-up。

## 4. 固定小扫描，不是全面验证

预先固定24配置：6/12服务器×4GPU，3DC均分；balanced与原生Zipf(.9)两个新种子860201/860203；平均每rank约16MiB，按同一实际总量归一化；WAN单向50/5000us。

- `shared`：服务器/网关/WAN=400/400/100Gbps。
- `capacity-sufficient`：服务器400Gbps；网关及每有向WAN为每DC服务器数×400Gbps，即800/1600Gbps，可承接本DC所有服务器满速收发，保留路径传播差异。

这些是独立策略的首轮探索，两个新种子在本轮使用后即为已见输入。24配置只涉及6个不同rank矩阵，机制两配置另复用1个矩阵；不是26份独立随机负载。Zipf控制全矩阵总量/平均预算，不限制每rank上限。

加机制共26配置×7方法=182结果。每方法先暖机一次，再3次轮转，只有规划量级诊断，不把三样本的最大值/nearest-rank p95当作稳定尾延迟；不声称达到实际在线截止时间。

### 4.2 是否有超出粒度的贡献

|方法，相对Max-Min|全部扫描|balanced|Zipf|
|---|---:|---:|---:|

带宽策略在容量充足场景没有接受候选，符合其纯串行化目标。时间策略在这组容量充足输入上有一致收益，但只覆盖当前两个规模/负载种子，不能外推全部层次网络。

## 5. 正例和负例

**带宽正例**：12服务器、balanced、共享WAN、单向50us。原生13.3770ms，带宽策略8.0825ms，1.6550×；总stage同为11，累计瓶颈串行化12.7935→7.6533ms，传播0.5808→0.4266ms。方法没有只靠stage粒度取胜，但也不能声称WAN stage数完全未变。

**时间正例**：12服务器、balanced、容量充足、单向5ms。原生56.2900ms，时间策略41.2858ms，1.3634×。总stage仍11，传播55.0308→40.0266ms，串行化同为1.256506ms，差15.0042ms来自传播重复暴露减少；原生机内计时不变。

**共同负例**：12服务器、Zipf860201、共享WAN、50us。原生20.1140ms；带宽策略20.6854ms（慢约2.84%），时间策略20.5594ms（慢约2.21%）。两者总stage均与原生相同，为115。

- 带宽策略累计串行化14.1406→14.7099ms，传播项相同。说明当前阶段的严格改善会改变后续残余，全程串行化仍可能更差。
- 时间策略累计传播5.9178→5.8664ms，但串行化14.1406→14.6375ms，后者增加超过前者减少。说明单路径时间目标看不到并发共享资源竞争。

两者的局限不同，为后续考虑组合提供了具体问题，但本轮没有实现联合策略，也没有证明简单相加或逐场景择优能泛化。

## 6. 规划成本与证据

最终顺序复跑的24配置中，各配置三次规划用时中位数再取中位数，带宽策略约389us、时间策略约160us、Max-Min约134us；不同规模/负载混合的这些量只作诊断，不能与旧报告CPU结果拼接。采集时本agent未同时运行测试/编译，但不保证主机其他活动隔离。

本机实现包含候选预测、路径准备和一致性trace；三次轮转不足以排除分配器状态或后台干扰，不据此声称时间策略部署开销一定更低。所有原始样本保留，报告的主要结论是确定性通信模型时间。

当前结论：两条路线已被分别实现并在机制输入上成立；带宽策略优先处理共享资源叠加，时间策略可减少慢路径在多stage上的重复暴露。它们在一般Zipf输入上仍受局部贪心、粒度及服务量保护限制。下一步应先解释上述共同负例，再讨论如何构造联合候选与控制全程代价，而不是立即宣布两个策略可以无条件叠加。
