## 最重要的判断

“集合通信应考虑物理拓扑”本身已经有充分积累，不能直接作为新颖性主张。更精确的研究对象应是：**在FAST的动态非均匀all-to-all需求、原有机内流程和低调度开销约束下，同时处理共享链路的流组合与Birkhoff阶段粒度。** 这仍只是待验证的定位，不是已证明的文献空白。

| 路线 | 优先读 | 对本工作的价值 | 迁移限制 |
|---|---|---|---|
| 阶段粒度与配置开销 | P07 Solstice、P06 Eclipse、P05 Birkhoff+ | 不只选边，还选择每阶段能搬多少真实数据 | 原论文常有电路重配置或近似需求，不能直接等同于WAN |
| 拓扑约束与离线模板 | P01 TACCL、P03 SyCCL、P08 HPDC All-to-All | 静态拓扑预处理，减少在线搜索 | 动态Zipf需求可能破坏对称性；聚合必须能还原合法端点匹配 |
| 网络容量与通信依赖 | P02 TE-CCL、P04 TACOS、P10 WAN依赖 | 正确描述共享资源、就绪流与后续代价 | 通用求解器/完整时间展开图可能过重 |
| 下界与已有工作边界 | P09 ForestColl、P11 Varys、P13 分层BvN预印本 | 避免目标混淆与重复发明 | AllGather理论、多coflow目标、队列稳定性不能冒充本题结论 |

与已有实验衔接：见[共享瓶颈实验报告](../../simulation/bottleneck/REPORT.md)。当前正例说明端点合法匹配仍可造成中间链路阶段性负载集中；反例说明局部链路效率更好不保证总完成时间更短。优先讨论稿中的方向A，而非继续强制“每阶段至少一条WAN流”。本轮没有修改任何调度器、计时模型或结果。
